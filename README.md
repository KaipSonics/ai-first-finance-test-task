# Тестовое задание · AI-first разработчик

### Финансовый отчёт по договорам, работам и авансовым платежам

> **Статус:** выполненное тестовое задание для отбора на позицию **AI-first разработчика**.  
> **Формат:** законченная CLI-программа на Python, исходные данные, воспроизводимые отчёты, автоматические тесты и объяснение бизнес-решений.

**Задача.** По договорам, перечню работ и истории платежей автоматически составить финансовый отчёт на заданную дату. Главная сложность — не чтение CSV, а неоднозначная бухгалтерская логика: часть авансов не привязана к работам, встречаются отмены, возвраты, платежи в очереди и операции после отчётной даты.

**Мой подход.** Не угадывать «ожидаемый ответ», а зафиксировать правила, отделить подтверждённые факты от предположений и сделать каждое распределение денег проверяемым.

---

## Что умеет решение

- **Работает на любую отчётную дату:** учитывает фактические даты платежей, возвратов, приёмки и отмены.
- **Считает точно до копейки:** `Decimal`, без денежных вычислений через `float`.
- **Распределяет авансы детерминированно:** сначала адресные платежи, затем общие по документированным правилам.
- **Не теряет исключения:** сохраняет отменённые работы в отчёте, выявляет переплаты, нераспределённые суммы и платежи в очереди.
- **Объясняет происхождение цифр:** отдельный аудиторский CSV связывает каждый учтённый платёж с работой.
- **Проверяет входные данные:** явные ошибки не приводят к «тихим» неверным результатам.
- **Создаёт отчёты для Excel:** CSV с `;`, десятичной запятой и UTF-8 BOM.

## Быстрый запуск

Требуется **Python 3.9 или новее**. Установка пакетов не нужна.

```bash
python -m src.cli --date 2026-11-10
```

Для другой даты:

```bash
python -m src.cli --date 2026-11-12
```

При необходимости можно переопределить каталоги с входными данными и отчётами:

```bash
python -m src.cli --date 2026-11-10 --data-dir ./data --output-dir ./output
```

Программа читает оригинальные CSV из `data/`. Готовые примеры за **10.11.2026** находятся в `output/`.

## Результат на контрольную дату

| Показатель | Договор D-1 | Договор D-2 | Итого |
|:--|--:|--:|--:|
| Договорная сумма | 600 000 ₽ | 90 000 ₽ | **690 000 ₽** |
| Стоимость действующих работ | 500 000 ₽ | 90 000 ₽ | **590 000 ₽** |
| Перечислено | 365 000 ₽ | 75 000 ₽ | **440 000 ₽** |
| Возвращено | 50 000 ₽ | 0 ₽ | **50 000 ₽** |
| **Фактически выплачено (нетто)** | **315 000 ₽** | **75 000 ₽** | **390 000 ₽** |
| Остаток по принятым работам | 0 ₽ | 0 ₽ | **0 ₽** |
| Остаток по будущим работам | 185 000 ₽ | 15 000 ₽ | **200 000 ₽** |

**Контроль:** `440 000 − 50 000 = 390 000 ₽` фактических выплат; `590 000 − 390 000 = 200 000 ₽` остатка по действующим работам. В выбранной модели **40 000 ₽** уже выплаченных авансов условно отнесены на ещё не принятые работы. Эти 200 000 ₽ **не следует путать с просроченной задолженностью**: сроки оплаты в данных не заданы.

## Инженерные решения

В тестовом задании нет единственного бесспорного способа распределить общие авансы. Поэтому ключевые правила **явно сформулированы**, а не спрятаны в коде:

1. Платёж без указания работы распределяется **внутри своего договора**: сначала по принятым работам, затем по будущим.
2. Платёж с указанием работы закрепляется **только за ней**; превышение её стоимости не переносится автоматически.
3. `queued` не считается выплатой; ошибочно перечисленный и возвращённый аванс не увеличивает чистую оплату.
4. Отменённая работа остаётся видимой для сверки, но исключается из текущей стоимости действующих работ.
5. Договорная сумма, стоимость действующих работ и фактические платежи выводятся **как разные показатели**.

Для каждого спорного решения в [`DECISIONS.md`](DECISIONS.md) указаны альтернативы, обоснование выбора и последствия изменения правила. Это существенная часть решения, а не формальность.

## Проверка качества

```bash
python -m unittest discover -s tests -v
```

**39 локальных автоматических тестов** успешно прошли. Проверяются дробные суммы, частичные оплаты, возвраты, даты до/после контрольной, прямые и общие платежи, отменённые работы, переплаты, некорректные CSV и согласованность итогов. В дополнение использован **независимый проверочный алгоритм на целых копейках**: 933 сверки на 13 отчётных датах.

Тесты запускаются стандартным `unittest` без внешних зависимостей. Это результат локальной проверки, а не статус CI GitHub.
